# 用户权限管理系统 - 完整接口文档

## 系统概述

本系统是一个基于Vue 3 + Element Plus的用户权限管理系统，提供用户管理、角色管理、权限控制和智能客服等功能。

### 技术栈
- **前端**: Vue 3 + Element Plus + Vue Router 4 + Axios
- **后端**: 基于RESTful API设计
- **认证**: JWT Token认证
- **权限**: 基于角色的权限控制(RBAC)

### 通用响应格式

所有接口都遵循统一的响应格式：

```json
{
    "code": 1,           // 响应码，1表示成功，0表示失败
    "msg": "success",    // 提示信息
    "data": {}           // 返回的数据
}
```

### 通用错误码

| 错误码 | 说明 |
|--------|------|
| 1 | 成功 |
| 0 | 失败 |
| 401 | 未授权/Token无效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

# 1. 用户管理

## 1.1 用户列表查询

### 1.1.1 基本信息
- **请求路径**: `/users`
- **请求方式**: `GET`
- **接口描述**: 该接口用于用户列表数据查询，支持分页和条件筛选

### 1.1.2 请求参数
参数格式：`queryString`

| 参数名称       | 是否必须 | 示例                          | 备注                                |
| ------------- | -------- | ----------------------------- | ----------------------------------- |
| username      | 否       | sadfaksj                      | 账号（模糊匹配）                    |
| name          | 否       | tom                           | 昵称（模糊匹配）                    |
| email         | 否       | 32423@qq.com                  | 邮箱地址（模糊匹配）                |
| createdStart  | 否       | 2024-01-01                    | 创建时间起始（含当天，YYYY-MM-DD）  |
| createdEnd    | 否       | 2024-01-31                    | 创建时间结束（含当天，YYYY-MM-DD）  |
| page          | 是       | 1                             | 分页查询的页码，默认为1              |
| pageSize      | 是       | 10                            | 分页查询的每页记录数，默认为10        |

**请求数据样例**:
```
/users?username=sadf&name=tom&email=4543@jds.com&createdStart=2024-01-01&createdEnd=2024-01-31&page=1&pageSize=10
```

### 1.1.3 响应数据
参数格式：`application/json`

| 参数名         | 类型        | 是否必须 | 备注                |
| -------------- | ----------- | -------- | ------------------- |
| code           | number      | 必须     | 响应码，1 代表成功，0 代表失败 |
| msg            | string      | 非必须   | 提示信息            |
| data           | object      | 非必须   | 返回的数据           |
| \|-total       | number      | 必须     | 总记录数            |
| \|-rows        | object[]    | 必须     | 数据列表            |
| \|-id          | number      | 非必须   | id                  |
| \|-username    | string      | 非必须   | 账号                |
| \|- name       | string      | 非必须   | 名字                |
| \|- email      | string      | 非必须   | 邮箱地址            |
| \|- createTime | string      | 非必须   | 创建时间            |
| \|- updateTime | string      | 非必须   | 更新时间            |

**响应数据样例**:
```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 2,
    "rows": [
      {
        "id": 1,
        "username": "admin",
        "name": "管理员",
        "email": "admin@example.com",
        "createTime": "2024-01-01 10:00:00",
        "updateTime": "2024-01-01 10:00:00"
      },
      {
        "id": 2,
        "username": "user1",
        "name": "普通用户",
        "email": "user1@example.com",
        "createTime": "2024-01-01 11:00:00",
        "updateTime": "2024-01-01 11:00:00"
      }
    ]
  }
}
```

### 4.1.1 基本信息
- **请求路径**: `/chat/conversations`
- **请求方式**: `POST`
- **接口描述**: 该接口是智能客服的核心交互接口。用户通过此接口发送消息，系统处理后返回客服的回复

### 4.1.2 请求参数
格式：`application/json`

| 参数名          | 类型   | 是否必须 | 备注                                                         |
| --------------- | ------ | -------- | ------------------------------------------------------------ |
| conversationId  | string | 否       | 会话ID。首次对话时可不传，后端将创建一个新的ID并返回。后续请求**必须**带上此ID，以保持对话上下文 |
| userId          | string | 否       | 用户ID。如果用户已登录，建议传入，便于客服查询与该用户相关的个性化信息 |
| message         | object | 是       | 用户发送的消息对象                                           |
| \|- type        | string | 是       | 消息类型，目前支持 "text"                                    |
| \|- content     | string | 是       | 消息内容                                                     |

**请求参数样例（首次对话）**:
```json
{
    "userId": "1",
    "message": {
        "type": "text",
        "content": "你好，我想查一下系统信息"
    }
}
```

**请求参数样例（在已有会话中继续对话）**:
```json
{
    "conversationId": "conv-xyz-789",
    "userId": "1",
    "message": {
        "type": "text",
        "content": "这个系统有哪些功能？"
    }
}
```

### 4.1.3 响应数据
参数格式：`application/json`

| 参数名            | 类型     | 是否必须 | 备注                |
| ----------------- | -------- | -------- | ------------------- |
| code              | number   | 必须     | 响应码，1 代表成功，0 代表失败 |
| msg               | string   | 非必须   | 提示信息            |
| data              | object   | 非必须   | 返回的数据对象       |
| \|- conversationId | string   | 必须     | 会话ID              |
| \|- replies       | object[] | 必须     | 回复列表            |
| \|- type          | string   | 必须     | 回复类型            |
| \|- content       | object   | 必须     | 回复内容            |

**`content` 结构说明**:

- 当 `type` 为 `text` 时, `content` 是一个对象: `{"text": "您好，请问有什么可以帮您？"}`
- 当 `type` 为 `card` 时, `content` 可能是: `{"title": "系统信息", "description": "...", "buttons": [{"text": "查看详情", "action": "..."}]}`
- 当 `type` 为 `options` 时, `content` 可能是: `{"title": "您可能想问：", "items": [{"text": "用户管理"}, {"text": "角色管理"}]}`

**响应数据样例（简单的文本回复）**:
```json
{
    "code": 1,
    "msg": "success",
    "data": {
        "conversationId": "conv-xyz-789",
        "replies": [
            {
                "type": "text",
                "content": {
                    "text": "您好！我是您的智能助手。这个系统是一个用户权限管理系统，主要功能包括用户管理、角色管理和权限控制。"
                }
            }
        ]
    }
}
```

**响应数据样例（包含建议选项的复杂回复）**:
```json
{
    "code": 1,
```

### 6.4.1 基本信息
- **请求路径**: `/logs/clear`
- **请求方式**: `DELETE`
- **接口描述**: 该接口用于清空所有系统日志

### 6.4.2 请求参数
无需请求参数

### 6.4.3 响应数据
参数格式：`application/json`

| 参数名 | 类型   | 是否必须 | 备注                |
| ------ | ------ | -------- | ------------------- |
| code   | number | 必须     | 响应码，1 代表成功，0 代表失败 |
| msg    | string | 非必须   | 提示信息            |
| data   | object | 非必须   | 返回的数据，此接口通常为null |

**响应数据样例**:
```json
{
    "code": 1,
    "msg": "清空成功",
    "data": null
}
```

# 7. 权限说明

## 7.1 权限数据表

系统采用数字ID作为权限标识，权限数据如下：

| 权限ID | 权限名称 | 权限描述 |
|--------|----------|----------|
| 1 | user:create | 添加用户 |
| 2 | user:update | 修改用户 |
| 3 | user:delete | 删除用户 |
| 4 | role:create | 添加角色 |
| 5 | role:update | 修改角色 |
| 6 | role:delete | 删除角色 |
| 7 | log:list | 查看日志 |
| 8 | user:list | 查看用户 |
| 9 | role:list | 查看角色 |

### 权限分类

#### 用户管理权限
- 权限ID 1 - 添加用户
- 权限ID 2 - 修改用户
- 权限ID 3 - 删除用户
- 权限ID 8 - 查看用户

#### 角色管理权限
- 权限ID 4 - 添加角色
- 权限ID 5 - 修改角色
- 权限ID 6 - 删除角色
- 权限ID 9 - 查看角色

#### 系统管理权限
- 权限ID 7 - 查看日志

## 7.2 预定义角色

### 超级管理员 (admin)
拥有所有权限：
- 权限ID: [1, 2, 3, 4, 5, 6, 7, 8, 9]

### 普通管理员 (manager)
拥有部分管理权限：
- 权限ID: [8, 9] (查看用户、查看角色)

### 普通用户 (user)
拥有基础权限：
- 权限ID: [8] (查看用户)

# 9. 接口调用示例

## 9.1 前端调用示例

### 用户登录
```javascript
// 登录
const loginData = {
    username: 'admin',
    password: '123456'
};

const response = await fetch('/api/login', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify(loginData)
});

const result = await response.json();
if (result.code === 1) {
    // 保存token
    localStorage.setItem('token', result.data.token);
    localStorage.setItem('userInfo', JSON.stringify(result.data));
}
```

### 获取用户列表
```javascript
// 获取用户列表
const token = localStorage.getItem('token');
const response = await fetch('/api/users?page=1&pageSize=10', {
    method: 'GET',
    headers: {
        'Authorization': `Bearer ${token}`
    }
});

const result = await response.json();
if (result.code === 1) {
    console.log('用户列表:', result.data.rows);
}
```

```javascript
// 发送消息给智能客服
const messageData = {

const response = await fetch('/api/chat/conversations', {
    method: 'POST',

        'Content-Type': 'application/json',
```
